# Burp Suite Testing

## Objective

Demonstrate the use of Burp Suite to intercept and inspect HTTP requests generated by the DVWA application and perform basic parameter fuzzing using Burp Suite Intruder.

## Environment

- Application: Damn Vulnerable Web Application (DVWA)
- Testing Environment: Localhost
- Tool: Burp Suite Community Edition
- Browser: Burp Suite built-in browser
- Target: Local DVWA application

---

# 1. Login Request Interception

## Description

Burp Suite Proxy can intercept HTTP requests between a browser and a web application.

This allows security testers to inspect request methods, parameters, headers, cookies, and other request data.

## Testing Procedure

Burp Suite Proxy interception was enabled and the DVWA login page was accessed through the Burp Suite browser.

The login form was submitted while interception was enabled.

## Observed Request

Burp Suite successfully intercepted the login request.

The request used the HTTP `POST` method and was sent to:

```text
/dvwa/login.php

The intercepted request contained parameters including:

username
password
Login
user_token

The password parameter was visible in the HTTP request body because the test environment uses a normal form submission.

Security Testing Value

Request interception allows a tester to:

Inspect HTTP requests.
Understand application parameters.
Identify sensitive information transmitted in requests.
Modify request parameters during authorized testing.
Analyze application behavior.
2. Burp Suite Intruder
Description

Burp Suite Intruder is used to automate repeated requests with different input values.

It can be used during authorized security testing for parameter fuzzing and input validation testing.

Configuration

The intercepted DVWA login request was sent to Intruder.

The following configuration was used:

Attack Type: Sniper
Target: Localhost DVWA
Parameter selected for testing: password
Payload type: Simple List
Test Payloads

The following values were used for the password parameter:

password
123456
admin
CSRFdemo123!
wrongpassword

Five payload values were configured for the Intruder attack.

Testing Procedure

The password parameter was marked as the Intruder payload position.

The attack was started using the configured payload list.

Burp Suite generated individual requests using the different payload values.

Observed Result

The Intruder attack generated multiple requests against the local DVWA login endpoint.

The resulting table allowed the requests and their HTTP responses to be compared.

The purpose of this test was parameter fuzzing and request-response analysis rather than attempting to obtain unauthorized access.

3. Security Considerations

Burp Suite should only be used against applications and systems for which testing authorization has been obtained.

Intercepting and modifying requests provides visibility into how applications process client-controlled parameters and can help identify weaknesses in input validation and request handling.

Conclusion

Burp Suite was successfully used to intercept and inspect a DVWA login request.

Burp Suite Intruder was then configured to fuzz the password parameter with a controlled list of test values. This demonstrated how Burp Suite can be used for HTTP request analysis and automated parameter testing during authorized web application security assessments.
