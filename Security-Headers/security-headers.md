# Web Security Headers Testing

## Objective

Configure and verify HTTP security headers in Apache for the local DVWA environment.

The headers were added to provide additional protection against common web application attacks and unsafe browser behavior.

## Environment

- Application: Damn Vulnerable Web Application (DVWA)
- Testing Environment: Localhost
- Web Server: Apache
- Configuration: Apache security headers
- Verification Tool: `curl`

---

# 1. Security Headers Configuration

The Apache security headers configuration was created in:

```text
/etc/apache2/conf-available/security-headers.conf

2. Header Configuration
Content-Security-Policy

The configured CSP restricts resources and scripts to approved sources.

default-src 'self'
script-src 'self'
object-src 'none'
base-uri 'self'

This also provides an additional layer of defense against certain forms of XSS.

X-Content-Type-Options
X-Content-Type-Options: nosniff

This instructs browsers not to perform MIME-type sniffing when interpreting resources.

X-Frame-Options
X-Frame-Options: SAMEORIGIN

This restricts the page from being framed by other origins and provides protection against certain clickjacking scenarios.

Referrer-Policy
Referrer-Policy: strict-origin-when-cross-origin

This controls how much referrer information is sent when navigating between resources.

Permissions-Policy
Permissions-Policy: geolocation=(), microphone=(), camera=()

This disables access to the listed browser capabilities for the application.

3. Apache Configuration Verification

The Apache configuration was tested before reloading the server.

The configuration test completed successfully with:

Syntax OK

Apache was then reloaded so that the security header configuration became active.

4. HTTP Header Verification

The configured headers were verified using:

curl -I http://localhost/dvwa/

The HTTP response returned the configured security headers, including:

Content-Security-Policy
X-Content-Type-Options
X-Frame-Options
Referrer-Policy
Permissions-Policy

The DVWA response returned:

HTTP/1.1 302 Found

The 302 Found response is part of the application's normal redirect behavior and does not prevent verification of the returned security headers.

5. SecurityHeaders.com

SecurityHeaders.com is a public service that can analyze HTTP security headers for publicly accessible websites.

The DVWA instance used during this internship was running only on localhost and was therefore not exposed as a public Internet-facing target.

For this controlled laboratory environment, the configured headers were verified directly using Apache configuration testing and curl.

No public exposure of the vulnerable DVWA application was required for the testing.

Conclusion

Security headers were successfully configured in Apache and verified through the HTTP response generated by the local DVWA application.

The configuration provides additional browser-side security controls and complements application-level security measures such as input validation, output encoding, CSRF protection and secure database handling.
