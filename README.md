# Task 3 — Web Application Security Testing

A practical web application security assessment performed using **Damn Vulnerable Web Application (DVWA)** in a controlled local laboratory environment.

This repository documents vulnerability testing, attack scenarios, security observations, and mitigation techniques covered during Task 3 of the Cybersecurity & Ethical Hacking Internship.

---

## 🎯 Objectives

The primary objectives of this task were to:

- Identify and demonstrate common web application vulnerabilities.
- Understand how vulnerable application functionality can be exploited.
- Analyze HTTP requests using Burp Suite.
- Demonstrate security controls and mitigation techniques.
- Configure and verify HTTP security headers.
- Document security testing results in a structured format.

---

## 🧪 Testing Environment

| Component | Details |
|-----------|---------|
| Application | Damn Vulnerable Web Application (DVWA) |
| Environment | Localhost / Controlled Laboratory |
| Web Server | Apache |
| Database | MariaDB |
| Operating System | Kali Linux |
| Proxy / Testing Tool | Burp Suite Community Edition |
| Browser | Burp Suite Built-in Browser |

All testing was performed against the local DVWA laboratory environment.

---

# 🔐 Security Testing Areas

## 1. SQL Injection

Demonstrated SQL Injection against the DVWA SQL Injection functionality.

### Testing included:

- Normal SQL query
- Boolean-based SQL injection
- UNION-based SQL injection
- Extraction of usernames and password hashes
- Prepared-statement based mitigation

📁 Documentation:

`SQL-Injection/`

---

## 2. Cross-Site Scripting (XSS)

Demonstrated multiple XSS scenarios and an additional browser-side mitigation.

### Testing included:

- Stored XSS
- Reflected XSS
- Content Security Policy (CSP)
- Verification of CSP through HTTP response headers

📁 Documentation:

`XSS/xss-testing.md`

---

## 3. Cross-Site Request Forgery (CSRF)

Tested the DVWA password-change functionality for CSRF protection.

### Testing included:

- Legitimate password change
- Tokenless password-change request
- Vulnerable implementation analysis
- CSRF token validation
- Verification of rejection of a tokenless request

📁 Documentation:

`CSRF/csrf-testing.md`

---

## 4. File Inclusion

Demonstrated both Local File Inclusion and Remote File Inclusion in the controlled DVWA environment.

### Testing included:

- Local File Inclusion (LFI)
- Reading `/etc/passwd`
- Remote File Inclusion (RFI)
- Controlled remote PHP file inclusion and execution

📁 Documentation:

`File-Inclusion/file-inclusion-testing.md`

---

## 5. Burp Suite Testing

Burp Suite was used to intercept and analyze HTTP requests generated by DVWA.

### Testing included:

- Login request interception
- HTTP request inspection
- Parameter analysis
- Intruder configuration
- Password parameter fuzzing

📁 Documentation:

`Burp-Suite/burp-suite-testing.md`

---

## 6. Web Security Headers

Security headers were configured in Apache and verified through HTTP responses.

### Headers configured:

- Content-Security-Policy
- X-Content-Type-Options
- X-Frame-Options
- Referrer-Policy
- Permissions-Policy

📁 Documentation:

`Security-Headers/security-headers.md`

---

# 🛡️ Security Controls Demonstrated

The task also covered practical mitigation techniques including:

- Prepared statements / parameterized queries
- Input validation
- Output encoding
- Content Security Policy
- CSRF tokens
- Secure HTTP security headers
- Least-privilege database access
- Secure handling of user-controlled input
